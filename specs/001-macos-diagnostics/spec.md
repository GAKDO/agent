# 기능 명세: AG1 macOS 진단 에이전트

**기능 브랜치**: `claude/project-thread-sy1p9l` (Spec Kit 기본값은 `feature/001-macos-diagnostics`)

**작성일**: 2026-11-02

**상태**: 초안

**입력**: 백로그 AG1 설명: "렌탈 노트북에서 실행하는 진단 에이전트(macOS 먼저)가 기기 식별·부품 구성, 배터리(사이클·설계·완충·최대 용량), SSD 상태, 고정 벤치마크 3회를 읽고, 결과를 먼저 보여 준 뒤 동의하면 페어링 코드로 받은 JWT로 올린다(FR-DIA-01~05, NFR-02). 결과는 contracts의 진단 JSON Schema를 따른다. 수용 기준: 팀 노트북 3대의 JSON이 저장된다. 배터리 값이 OS 배터리 리포트와 같다. SSD를 못 읽으면 사유가 남는다. 전원이 연결되지 않으면 벤치마크를 돌리지 않는다. 동의 없이는 전송되지 않는다. 읽는 경로 목록이 고정되고 사용자 파일·브라우저 기록을 읽지 않는다. 참고: design/diagnostics-json-v0.md의 macOS 실제 키."

**요구사항 ID**: FR-DIA-01, FR-DIA-02, FR-DIA-03, FR-DIA-04, FR-DIA-05, NFR-02

## 명확화

### 세션 2026-11-02

- Q: 에이전트는 어떻게 실행하나요? → A: 운영 담당이 렌탈 노트북 터미널에서 `trace-agent run --code <6자리>`를 실행한다. 결과 요약을 보여 주고 "올릴까요? [y/N]"에 y를 넣어야만 올린다. 설치 파일(.pkg)과 GUI는 범위 밖
- Q: SSD 수명 값은 어디서 읽나요? → A: `smartctl -j -a disk0`. smartctl이 없거나 실패하면 SSD는 `SKIPPED`, 사유는 `TOOL_ERROR`. 권한 오류면 `NO_PERMISSION`, NVMe·ATA가 아니면 `UNSUPPORTED`
- Q: 발열 상태(thermalState)는 어떻게 정하나요? → A: `pmset -g therm`에 경고 기록이 없으면 `NOMINAL`, 경고가 있으면 `FAIR`, 읽지 못하면 null. 더 세밀한 값(SERIOUS·CRITICAL)은 쓰지 않는다(파이썬에서 ProcessInfo.thermalState를 바로 읽을 수 없음)
- Q: OS 판정은 어떻게 바꾸나요? → A: codes.yaml 0.4.0 주석대로 `sppower_battery_health`가 "Good"·"Normal"이면 `NORMAL`, 그 밖은 `SERVICE_RECOMMENDED`
- Q: 서버 주소는? → A: 환경 변수 `TRACE_API_URL`(gateway 주소). 기본값 없음

## 사용자 시나리오와 테스트 *(필수)*

### 사용자 스토리 1 - 진단 결과를 보고 확인한다 (우선순위: P1)

운영 담당이 렌탈 맥북에서 에이전트를 실행하면, 기기·부품·배터리·SSD·측정 조건을 읽어 진단 JSON을 만들고 사람이 읽을 요약을 보여 준다. 무엇을 실행했는지(`sources`)도 함께 보인다.

**우선순위 이유**: 진단 비교(DI1·DI2)와 리포트의 내부 상태가 모두 이 JSON에서 시작한다.

**독립 테스트**: 실제 맥에서 받은 명령 출력 고정 파일을 넣어, 만든 JSON이 contracts 스키마를 통과하고 배터리 값이 고정 파일의 OS 값과 같은지 확인한다.

**수용 시나리오**:

1. **주어진 상황** 맥 명령 출력이 있을 때, **동작** 진단을 만들면, **결과** contracts 진단 JSON Schema(diag.v1)를 통과한다.
2. **주어진 상황** OS 배터리 정보에 사이클 214, 최대 용량 89%가 있을 때, **결과** JSON의 `cycleCount`·`osMaxCapacityPercent`가 같고, 설계·완충 용량은 ioreg의 mAh 값 그대로다.
3. **주어진 상황** smartctl이 없거나 실패할 때, **결과** SSD는 `SKIPPED`와 사유가 남고 값은 모두 null이다.
4. **주어진 상황** OS가 사이클을 0으로 줄 때, **결과** `cycleCount`는 null이다(0을 "모름"으로 쓰지 않음).
5. **주어진 상황** 명령 출력에 컴퓨터 이름·플랫폼 UUID가 있을 때, **결과** JSON 어디에도 그 값이 없다.

---

### 사용자 스토리 2 - 전원이 있을 때만 벤치마크를 돌린다 (우선순위: P1)

전원이 연결돼 있으면 고정 벤치마크 5종(CPU 단일·멀티, 메모리 복사, 디스크 읽기·쓰기)을 3회씩 돌려 중앙값을 낸다. 전원이 없으면 돌리지 않고 사유를 남긴다.

**독립 테스트**: 전원 상태를 바꿔 끼운 가짜 출력으로 벤치마크 실행 여부와 결과 형식을 확인한다.

**수용 시나리오**:

1. **주어진 상황** 전원이 연결되지 않았을 때, **결과** 벤치마크를 하나도 실행하지 않고 `benchmarks: []`, `benchmarkSkippedReason: NO_AC_POWER`다.
2. **주어진 상황** 전원이 연결됐을 때, **결과** 지표 5개가 각각 trials 3개와 그 가운데 값인 median을 가진다.

---

### 사용자 스토리 3 - 동의한 뒤에만 올린다 (우선순위: P1)

요약을 본 운영 담당이 y를 넣으면 페어링 코드를 AGENT JWT로 바꾸고 진단 JSON을 올린다. 동의 시각이 `consentedAt`으로 남는다.

**독립 테스트**: 가짜 HTTP로 동의·거절·서버 오류 흐름을 돌린다.

**수용 시나리오**:

1. **주어진 상황** 요약 뒤 y 말고 다른 것을 넣으면, **결과** 어떤 네트워크 요청도 보내지 않고 끝난다.
2. **주어진 상황** y를 넣으면, **결과** 페어링 코드 교환 뒤 `POST /api/v1/diagnostics/runs`에 `Idempotency-Key`와 함께 올리고, 본문의 `consentedAt`은 y를 넣은 시각이다.
3. **주어진 상황** 서버가 422(스키마·시리얼 불일치)나 409(이미 올림)를 주면, **결과** Problem Details의 code를 보여 주고 0이 아닌 코드로 끝나며 JSON을 파일로 남긴다.

### 경계 상황

- 배터리가 없는 맥(데스크톱)이면 `battery.status`는 `NO_BATTERY`이고 값은 모두 null이다.
- 페어링 코드가 틀리거나 만료되면 무엇이 틀렸는지 알리고, 토큰 값은 출력하지 않는다.
- 고정 목록에 없는 명령은 실행 함수가 거절한다(테스트로 막음).
- 만든 JSON이 스키마를 통과하지 못하면 올리지 않고 어느 필드인지 알린다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 기기 시리얼·제조사·모델 식별자·모델 이름과 부품(CPU·RAM·SSD·BATTERY·DISPLAY)을 읽는다(FR-DIA-01).
- **FR-002**: 배터리 사이클·설계 용량·완충 용량(mAh 그대로)·OS 최대 용량 %·OS 판정을 읽는다(FR-DIA-02).
- **FR-003**: SSD 사용률·예비 블록·경고·미디어 오류·가동 시간을 읽고, 못 읽으면 `SKIPPED` + 사유를 남긴다(FR-DIA-03).
- **FR-004**: 측정 조건(전원·잔량·발열·프로세스 수·가동 시간)을 남기고, 전원이 있을 때만 벤치마크 5종 × 3회와 중앙값을 낸다(FR-DIA-04).
- **FR-005**: 결과를 보여 주고 동의를 받은 뒤에만 페어링 JWT로 올린다(FR-DIA-05).
- **FR-006**: 실행하는 명령은 코드 상수의 고정 목록뿐이고, 사용자 파일·브라우저 기록을 읽지 않는다. 컴퓨터 이름·사용자 이름·플랫폼 UUID는 보내지 않는다(NFR-02).
- **FR-007**: 올리기 전에 contracts 진단 JSON Schema(diag.v1)로 검증한다.

### 핵심 데이터

- **진단 결과**: contracts `diagnostics/result.schema.json` diag.v1 그대로
- **명령 출력**: 고정 목록의 명령 하나와 그 표준 출력·종료 코드

## 성공 기준 *(필수)*

- **SC-001**: 팀 노트북 3대의 JSON이 스키마를 통과하고 서버에 저장된다(DI1 이후 확인).
- **SC-002**: 배터리 값이 OS 배터리 정보(시스템 정보 앱의 전원 항목)와 같다.
- **SC-003**: 전원이 없으면 벤치마크 실행 0회, 동의가 없으면 네트워크 요청 0회.
- **SC-004**: 실행한 명령이 모두 고정 목록 안에 있다.

## 가정

- 대상은 Apple Silicon·Intel 맥, macOS 14 이상, Python 3.12.
- smartctl은 운영 담당이 미리 설치한다(`brew install smartmontools`). 없으면 SSD는 생략 사유로 남는다.
- 서버 저장(SC-001)은 diagnostics-server DI1(A, 11/7)과 auth-server 페어링(AU1)이 나온 뒤 확인한다.
- Windows는 AG2 범위다.
